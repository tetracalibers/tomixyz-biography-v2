色彩学やCG・画像処理について、インタラクティブに学べるWebサイトです。

**「見て・触って学ぶ」** をコンセプトに、色彩検定やCG-ARTS検定の学習で登場する知識の暗記学習を、Webならではの体験に置き換えることを目指しています。

## 学ぶ・見分ける・使う

コンテンツは、知識を暗記するだけで終わらないように設計しています。

1. まずは[色の理論](https://color-prism.net/color-theory/)で光・色・視覚の基礎を体系的に学ぶ
2. 次に、[明度比較](https://color-prism.net/games/lightness-match/)や[トーン当てクイズ](https://color-prism.net/games/tone-match/)を通して、知識として覚えた色の違いを自分の目で見分ける
3. さらに、[配色分析](https://color-prism.net/analyze/)や[配色シミュレータ](https://color-prism.net/patterns/)を使って、自分で色を選び、組み合わせてみる
4. 最後は、（オプションとして）光と色の知識を[CG・画像処理](https://color-prism.net/cg/)へつなげていく

暗記した知識を、少しずつ「使える感覚」へ変えていくことを目指しました。

## 「知りたいこと」から辿れる構造

コンテンツの分類にも工夫があります。

資格試験のカリキュラムに沿って知識を整理するだけでは、試験が終わったあとに「どこに何が書いてあったか」を辿りにくくなります。
2級のある単元は、3級のある単元の発展であることも多いです。そこで、級ごとではなく、単元ごとに整理し、興味に沿って級を超えて深く学んだり、色彩検定を目的としない人でも楽しめる構成にしました。

級は分類ではなくタグとして持たせることで、試験勉強なら必要な範囲だけを拾い読みでき、興味があれば級を越えてそのまま深掘りできます。

たとえば「色の理論」には、色彩検定3級・2級・1級・UC級の内容が含まれています。

しかし、ページ自体は級ごとには分けていません。

- 「色の表し方」
- 「色が見えるしくみ」
- 「色の作り方と色再現」
- 「色の見え方」

といった**テーマを軸に記事を構成**し、級はタグとして表示しています。

試験勉強なら必要な級だけを拾い読みできる。一方で、興味のあるテーマなら級の壁を越えてそのまま深掘りできる。
資格試験のための教材でありながら、試験が終わったあとにも使える「色のリファレンス」を目指した設計です。

# Color Prism

**見て、触って、色を理解する。**

Color Prism は、色彩についてインタラクティブに学べるWebサイトです。

色彩検定とCG-ARTS検定の学習範囲をベースに、文章を読むだけでは理解しづらい色や光の現象を、図解・クイズ・シミュレータ・3Dデモを通して体験できる教材として設計しました。

---

## Overview

### 「読む」だけではない、色彩の学習サイト

Color Prism のコンセプトは、**「見て・触って学ぶ 色彩の暗記帳」**。

色彩検定（3級・2級・1級・UC級）とCG-ARTS検定（CGエンジニア／画像処理エンジニア エキスパート）の範囲を土台に、149本の記事と約200点の図解・デモコンポーネントを制作しています。

サイト全体は、

**読む → 見分ける → 作る → 発展させる**

という流れで構成しました。

色の理論を学び、クイズで違いを見分け、ツールを使って配色を試し、その先でCGや画像処理へ進む。

知識を暗記するだけではなく、**自分の目で確かめながら「使える知識」にしていくこと**を目指しています。

---

## Challenge

### 色の話なのに、色を「体験」する機会が少ない

色彩について学んでいると、文章だけでは理解しづらい場面が何度もあります。

「同じ明度なのに、なぜ違う明るさに見えるのか」
「トーンが変わると、色の印象はどう変わるのか」
「光の干渉によって、なぜ色が生まれるのか」

こうした現象は、説明を読むだけでなく、**実際に比較したり、動かしたりすることで初めて腑に落ちる**ことがあります。

一方で、資格試験のカリキュラムに沿って知識を整理するだけでは、試験が終わったあとに「どこに何が書いてあったか」を辿りにくくなります。

さらに、記事や図解が増えていけば、一覧、ナビゲーション、OGP、公開時の作業など、コンテンツそのものとは別の運用コストも増えていきます。

そこで、

**どうすれば、色を体験として理解できるか。**
**どうすれば、試験の級を越えて知識を辿れるか。**
**どうすれば、コンテンツが増えても1人で改善し続けられるか。**

この3つを、同じプロジェクトの課題として考えました。

## Approach

### 学習体験から、サイト全体を逆算する

Color Prism では、資格試験の区分ではなく、**「何について学んでいるか」**を軸にコンテンツを整理しています。

たとえば「色の理論」では、色彩検定3級・2級・1級・UC級の内容を、

「色の表し方」
「色が見えるしくみ」
「色の作り方と色再現」
「色の見え方」

といった9カテゴリ、78記事に再構成しました。

級は分類ではなくタグとして持たせることで、試験勉強なら必要な範囲だけを拾い読みでき、興味があれば級を越えてそのまま深掘りできます。

そして、**言葉で説明するより見せた方が速いものは、積極的にインタラクティブな教材へ置き換える**ことにしました。

読むだけではなく、比較する。
覚えるだけではなく、答えてみる。
理論を知るだけではなく、自分で色を選んでみる。

UIや技術を先に決めるのではなく、**「どうすれば正しく理解できるか」から必要な体験を決める**ことを基本方針にしています。

## 色を「見る・見分ける・使う」ための体験

Color Prism には、記事を読む以外にも、色彩を体験するための機能があります。

### 色を体系的に学ぶ

「色の理論」では、光・色・視覚について78記事で体系化。

同時対比、干渉、回折、色立体など、紙面ではイメージしづらいテーマには、SVGやThree.jsによるインタラクティブな図解を組み込んでいます。

ヘッダーから**暗記モード**に切り替えると、重要語や色名が伏せられ、読んでいたページがそのまま穴埋め問題になります。

### 似た色を、比較して覚える

「慣用色名マップ」では、127色の慣用色を**色相 × 明度**の位置関係に配置しました。

名前と色を1色ずつ暗記するのではなく、

「こちらの方が明るい」
「こちらの方が赤みに近い」

という相対的な違いから覚えられます。

紛らわしい色については、色相・明度・彩度のうち実際に異なる軸だけを図示し、**何を見比べればいいのか**まで提示します。

### 「分かったつもり」をクイズで確かめる

明度比較、清色・濁色、トーン当ての3種類のクイズを用意しました。

ただし、スコアやランキング、制限時間はありません。

目的は競うことではなく、**間違えながら自分の知覚を較正すること**だからです。

たとえば明度比較では、色相や彩度が手がかりにならないよう、あえて似た候補を出題します。

トーン当てでは、正解トーンの隣にある紛らわしいトーンを優先的にはずれ札にすることで、「なんとなく」では答えられない問題を生成しています。

### Webの色を、色彩理論の言葉へ変換する

「色の近似」では、HEXカラーから近いPCCS記号と慣用色名を検索できます。

「配色の分析」では、2〜6色の配色を色相環とトーン図へプロットし、ドミナントカラー、カマイユ、トライアドなど、**色彩検定で学ぶ言葉を使って配色の特徴を説明**します。

「配色シミュレータ」では、エレガント、クラシック、モダンなど10テーマから色を選び、完成した配色を幾何パターンへリアルタイムに反映。

学んだ色彩理論を、実際に色を選ぶ体験へつなげています。

### 色彩から、CG・画像処理へ

色彩の先には、CG・画像処理を学ぶ26ユニット・45記事を用意しました。

透視投影、座標系、屈折、反射、干渉、回折などは、Three.jsによるデモを操作しながら学べます。

CGの記事では、**実際に動いているデモのコードも掲載**。

「見て理解する」だけでなく、Web制作へ持ち帰って自分で実装できるところまでを学習体験に含めています。

## 光と色の知識を、CGの計算へつなげる

Color Prism のもう一つのテーマが、色彩からCG・画像処理への橋渡しです。

きっかけは、CGを学び始めたときに、教科書に出てくる光の計算式をうまく理解できなかったことでした。

CGの式だけを見るのではなく、その前に光や色そのものを理解していたら、もっと自然に学べたのではないか。

その経験から、色彩の基礎を学んだ先に、CG-ARTS検定の範囲をベースにした26ユニット・45記事を配置しました。

透視投影、座標系、屈折、反射、干渉、回折などは、Three.jsによるデモを操作しながら学べます。

さらにCGの記事では、**画面上で動いているデモのコードも掲載**しています。

現象を理解するだけでなく、「これをWebで作るならどう実装するか」まで持ち帰れる教材にしています。

## 「教材として正しいか」を、実装判断の基準にする

Color Prism は、SvelteKit 2 / Svelte 5 / TypeScript を中心に構築しています。

記事は `.svx`（mdsvex）で管理し、独自のremarkプラグインによって、数式、暗記用コンポーネント、図解、Mermaid、コードなどをMarkdownから扱えるようにしました。

図解は原則としてインラインSVGのSvelteコンポーネントとして実装し、3D表現にはThree.js / Threlteを使用しています。

技術選択で重視しているのは、**教材としての意味と実装が食い違わないこと**です。

たとえば明度比較クイズのヒントでは、CSSの `grayscale()` を使っていません。

CSSのグレースケールとゲームで正解判定に使うマンセルValueでは基準が異なるため、Valueからグレーを計算し、**同じValueなら必ず同じグレーになる**ようにしています。

出題ロジックも純関数として切り出し、

「正解が偶発的に混ざらない」
「同じ候補が重複しない」

といった学習体験に関わる不変条件をテストしています。

また、ICC変換、マンセルからRGBへの変換、数式レンダリング、シンタックスハイライトなど、事前に決められる重い処理はできるだけビルド時・生成時に寄せています。

実行時に残すのは、ユーザーの操作によって変わる部分だけ。

教材としての正確さと、静的サイトとしての軽さを両立させています。

## AIが扱う情報量そのものも設計する

自動化を進める中では、AIに何を読ませるかも設計対象になりました。

たとえば文体分析では、ルール、根拠、未採用の観察を3層に分離。

記事が増えるほど証拠は増えても、**執筆するAIが読む情報量は記事数に比例して増えない**構造にしています。

また、エージェント間通信による待ち状態で処理が止まった経験から、分析フローの制御をJavaScriptへ移し、独立したエージェントの構造化出力を決定論的にオーケストレーションする方式へ変更しました。

失敗したら、その場だけ直すのではなく、**同じ失敗が起きないように仕様や構造へ戻す**。

プロダクトだけでなく、それを作り続ける開発環境まで含めて改善しています。

## 「色を扱うサイト」だからこその実装

Color Prism は、SvelteKit 2 / Svelte 5 / TypeScript を中心に構築しています。

記事は Markdown ベースで管理しつつ、独自の remark プラグインを使って、数式、図解、暗記用コンポーネント、コードなどを教材として扱えるように拡張しています。

図解は画像として貼るのではなく、SVGやThree.jsを中心にコンポーネント化。

色そのものが教材になるため、ライト／ダークテーマを切り替えても教材の意味が変わらないことや、色変換の計算と画面上の見え方が食い違わないことも重視しています。

たとえば明度クイズのヒントでは、単純なCSSの `grayscale()` は使っていません。

ゲームの正解判定に使っているマンセルValueからグレーを計算し、**「正解判定」と「ユーザーが見るヒント」が同じ基準になるようにする**。

小さな実装判断でも、「学習者に間違った理解を与えないか」から逆算しています。
