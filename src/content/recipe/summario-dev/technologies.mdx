## フレームワーク：React Router

[React Router](https://reactrouter.com/) v7系の[Framework Mode](https://reactrouter.com/start/modes#framework)をベースに、フロントエンドとバックエンドを共存させる形で開発しています。

構想をまずは形に起こしてみたいということで、エコシステムが充実しているReactを選びましたが、プロトタイプ段階ゆえ、メインのフレームワークにはなるべく依存したくありませんでした。

[Next.js](https://nextjs.org/)のApp Routerも学びがいがあり、選択肢の一つだったのですが、Next.jsの場合「フレームワークが何かしてくれているから動く」「コードがフレームワーク特有の書き方に染まる」という状況に陥りかねないと感じたのです。

React Routerの方がWeb標準に近いことも魅力に感じていましたが、結局React Routerの思想に乗せきれなかった部分もあり、React Routerの機能を徹底的に使いこなすというよりは適材適所で薄く使う形になっています。
この辺りの詳細は回を改めて書けたらいいなと思います。

## ORM：Drizzle

TypeScriptで使えるORMといえば[Prisma](https://www.prisma.io/orm)が人気という印象を受けます。
Prismaではなく[Drizzle](https://orm.drizzle.team/)を選んだのは、いざとなったら生のSQLを書きたかったからです。

- [【T3 Stack入門】ORM比較（Prisma VS Drizzle）](https://zenn.dev/maicom/articles/f42edb80db3a1c)

Summarioにはノートをグルーピングできる「フォルダ」機能がありますが、フォルダの階層構造をRDB上ではAdjacency List Model（隣接リストモデル）で表現しています。
このモデルでは、データを`SELECT`する際に`WITH RECURSIVE`句による再帰CTE（ざっくりいえばSQLで再帰処理を実現する構文）を活用することになりますが、この`WITH RECURSIVE`句など、ORMのAPIではまだサポートされていないSQL構文を使う可能性があったため、drizzleを採用しました。

## エディタ機能：Tiptap

Summarioのノート編集画面に組み込まれているエディタは、Headless Editor Frameworkである[Tiptap](https://tiptap.dev/)を使って実装しています。

Tiptapに興味を持ったのは、[Zenn](https://zenn.dev/)の作者catnoseさんが開発されている執筆サービス「[しずかなインターネット](https://sizu.me/home)」でも使われているということからでした。

- [しずかなインターネットの技術構成](https://zenn.dev/catnose99/articles/f8a90a1616dfb3)

### 高いモジュール性

まとまった機能を備えるWYSIWYGエディタライブラリはオーバースペックになりがちですが、Tiptapが提供するコア機能は最小限です。
[Extension](https://tiptap.dev/docs/editor/extensions/overview)で欲しい機能だけを追加していくため、過不足なく要件を実現することができます。

公式Extensionの粒度はとても小さく、例えばMarkdown記法のサポートは構文ごとにExtensionが用意されています。
エディタ上でサポートしたい構文を1つずつセットアップするのはやや面倒な作業ですが、[StarterKit](https://tiptap.dev/docs/editor/extensions/functionality/starterkit)を使えば、主要なMarkdown記法をサポートするExtensionをまとめて導入することができます。

また、独自のExtensionを実装することで、独自の機能の追加や、細かい挙動の制御も可能です。

### ProseMirror由来の高度なカスタマイズ性

Tiptapは[ProseMirror](https://prosemirror.net/)というリッチテキストエディタ構築ツールキットを使いやすくラップしたライブラリであり、ProseMirrorの高いカスタマイズ性を継承しながら、実装や学習のコストを大幅に抑えてくれています。

ProseMirrorベースだからこそ実現できる機能として、スキーマによる文書構造の強制などがあります。

Tiptapは単なるリッチなテキストエリアとして使えるだけでなく、「最上部には必ずタイトルを書いてほしい」などといった、文書構造の規則を定めることができます。
これはProseMirrorのスキーマという概念によって実現できるもので、Tiptap（ProseMirror）では、設定したスキーマで禁止されている構造は絶対に作れないようになっています。

また、独自のExtensionを実装する際にも、TiptapのAPIだけでは実現できない場合はProseMirrorのAPIにアクセスすることができます。

### UIのサポート

"Headless" Editorということで、基本的にエディタUIの実装は独自に行うことになりますが、必要に応じて公式の[UIコンポーネント](https://tiptap.dev/docs/ui-components/getting-started/overview)を使うこともできます。
