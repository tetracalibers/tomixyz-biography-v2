**人間とAIが一度決めたことを、何度でも再利用できる画像生成パイプライン。**

Color Prismの150以上のページに対して、ページ固有のOGP画像を生成・管理・配信する仕組みを設計しました。

## 152ページ、それぞれに固有のOGP画像を

Color Prismは、記事・ツール・ゲームを合わせて150以上のページを持つ色彩学習サイトです。

SNSで共有されたときに「どのページなのか」がカードだけで伝わるよう、**152ページそれぞれに固有のOGP画像**を用意しました。

サイト既定画像を含め、現在の生成数は153枚。

そのうち60枚には、記事で実際に使っているSVG図解やThree.jsデモを組み込んでいます。

画像は1200×630pxのPNGとして生成し、サイトと同じロゴグラデーションや配色を使用。

単なるサムネイルではなく、**Color PrismのUIがそのままSNSへ続いているようなカード**を目指しました。

## 「画像生成」より「判断」がボトルネックになる

OGP画像には、自動化しやすい処理と、自動化しづらい判断が混在します。

タイトルをどこで改行するか。  
記事を代表する図版はどれか。  
白背景を透過した方が自然に見えるか。

これらは、文字数やファイル順だけでは決められません。

一方で、一度決めたことをテンプレート変更のたびに聞き直していては、ページ数に比例して運用コストが増えていきます。

さらに、

- SVGからPNGを安定して生成する
- 図版とカードのテーマを自然になじませる
- フォントやテキスト組版の環境差をなくす
- SSRを使わないページでもSNSクローラへOGPを届ける
- 未生成ページがあってもサイトを壊さない

といった、画像生成の前後にも課題がありました。

そこで、OGPを単発の画像生成処理ではなく、**判断・描画・記録・再生成・配信までを含むパイプライン**として設計しました。

## 「知能が必要な処理」と「決定的な処理」を分ける

基本方針はシンプルです。

**判断には人間とAIを使う。  
一度決まったことには、もう知能を使わない。**

生成処理を3層に分けました。

**知能層**では、Claude Codeのスキルがページを読み、タイトルやパンくずを取得。カードの種類やテーマを判定し、改行位置、図版、透過方法など、必要な項目だけ人間へ確認します。

**描画層**では、確定した値をJSONとして受け取り、SVGテンプレートからPNGを生成。同時に、その判断結果と使用した図版を永続化します。

**自動化層**では、保存済みの記録だけを読み、AIとの対話なしで全画像を再生成します。

この境界によって、AIとの対話を使い捨てにせず、**一度行った判断を再利用可能なデータへ変換**しています。

## Key Features

### ページ固有のカード

152ページそれぞれにタイトルと画像を用意。

記事カードには「色の理論 › 色が見えるしくみ」のようなパンくずも焼き込み、SNS上でカード単体を見ても、そのページの位置づけが分かるようにしています。

一方、ツールやゲームはタイトルを中心にした別レイアウトを使用。

**ページの性格とカードの型を対応**させています。

### 60枚の図版入りカード

記事内で使っているSVG図解やThree.jsデモを、OGPにも活用しています。

図版は自動選択しません。

「どのカットが記事を代表するか」は著者が判断し、一度選択した画像を生成用アセットとして保存します。

**判断だけは人間に残し、同じ作業を繰り返さない**設計です。

### サイトと共通した視覚言語

ロゴにはWebサイトと同じグラデーションを使用。

CG・画像処理の記事では、Three.jsデモと同じ背景色をカードにも採用しています。

図版の背景とカードの地色を合わせるだけでなく、必要に応じて装飾も消し、スクリーンショットの矩形が浮かないところまで調整しました。

### 未生成でも壊れないフォールバック

すべてのカードが揃っていることを前提にはしていません。

ページ固有のOGPがまだ存在しない場合は、サイト既定画像とサイト名へ自動的にフォールバックします。

OGP整備を、**「全部揃わないと公開できない義務」ではなく、「増やすほどサイトが良くなる資産」**として扱えるようにしています。

## SVG + resvg-jsによるブラウザレス描画

画像生成にはPuppeteerやPlaywrightを使わず、4種類のSVGテンプレートを`resvg-js`でPNGへ変換しています。

OGP生成環境はSvelteKit/Viteから独立したNodeパッケージとして構成。

Webアプリを起動せず、画像だけを再生成できます。

### テキスト実測なしでタイトルを組版

resvgにはブラウザのようなテキスト実測APIがありません。

そこで、全角・大文字・細い英字などの文字種から幅を概算。

領域を超える場合はフォントサイズと字間を同率で縮小し、1行・2行どちらでもタイトルブロックの中心が変わらないよう再配置します。

3行以上は自動処理せずエラーにすることで、**自動化する範囲そのものを制限**しています。

### レンダラが扱えるフォントへ前処理

環境差を避けるため、システムフォントは使用していません。

可変フォントをresvgが正しく扱えない問題には、ウェイト確定済みの静的フォントへ変換して対応。

さらにフォント内部のファミリー名が一致しないケースでは、TTFの`name`テーブルを自前で書き換えています。

**レンダラの制約を回避するのではなく、入力をレンダラが確実に扱える状態へ変換する**方針です。

### 「規則」と「ページ固有の値」を分離

カードのバリエーションやテーマはページごとのJSONには保存せず、ルートから毎回導出します。

たとえば「`/cg/**`はダークテーマ」という規則を1か所変更すれば、次回の全再生成ですべてのCG記事へ反映されます。

一方、タイトルの改行や選択した図版など、ページ固有の判断だけをJSONへ保存。

**全体へ波及する規則と、個別の判断を別々の単一情報源として管理**しています。

### 静的HTMLへOGPタグを直接焼き込む

Color Prismには、ブラウザAPIなどを使うためSSRを無効にしたページがあります。

そのままでは、JavaScriptを実行しないSNSクローラにOGPタグが届きません。

そこで全ルートをプリレンダし、ビルド後に各HTMLの`<head>`へOGP/Twitter Cardタグを静的注入。

サーバーやEdgeでHTMLを書き換えず、**100%静的なサイトのままSNSクローラへの配信まで完結**させています。

## 一度した対話を、二度しない

Claude Codeの`generate-ogp-image`スキルが、ページ解析から画像生成までの入口を担当します。

AIが改行案などを提示し、人間が確認。

確定した

- タイトルと改行位置
- パンくず
- 使用する図版
- 必要なテーマ上書き

などをページごとのJSONへ保存します。

一度選択した図版も永続化するため、テンプレートを変更した後は、

`npm run regenerate`

だけで全画像を対話なしで再生成できます。

**AIが出した答えを保存するのではなく、人間との対話で確定した判断を、次の自動化が読める形式で保存する。**

そこを自動化の境界にしています。

### 単発生成と一括生成で、失敗の扱いを変える

手動で行う単発・部分生成は**fail-fast**。

1件でも入力が不正なら、画像を書き出す前に処理全体を停止します。

一方、153枚を作り直す一括再生成は**robust**。

1ページで失敗しても残りを続行し、最後に成功件数と失敗一覧を報告します。

同じ描画処理でも、**「誰が・何のために実行するか」によってエラー戦略を変えています。**

### 破壊的な処理を初回だけに閉じ込める

白背景を透過する処理にはImageMagickを使いますが、加工済み画像を永続アセットとして保存します。

そのため、再生成やCIにはImageMagickが不要です。

**一度終わった重い処理や判断を保存し、下流へ依存を持ち込まない。**

画像処理でも、AIとの対話でも、同じ設計思想を適用しています。

## Result

**ページが増えても、デザインが変わっても、過去の判断を失わずに作り直せること。**

OGP画像を「一度作って終わる成果物」ではなく、サイトと一緒に育てられる資産として扱える生成パイプラインを構築しました。
