argument-hint: [PR番号（省略時は現在のブランチのPR）]

現在のブランチのPRについて、説明文とタイトルをブランチの実際の中身に合わせて書き直してください。

対象：$ARGUMENTS

## 現状を調べる

1. `gh pr view --json number,title,body,baseRefName`で今の説明文とタイトルを取得する（説明文は古くなっている前提で読む）
2. `git fetch origin main`のあと、次でブランチの全体像を把握する
   - `git diff --name-status -M origin/main...HEAD` — 追加・変更・削除・**リネーム**（`R`）を区別する
   - `git diff --stat origin/main...HEAD` — 変更量
   - `git log --oneline origin/main..HEAD` — 経緯（途中でRevertや切り出しをしていないか）
3. 記事ファイル（`src/content/`）については、公開状態を1本ずつ確認する
   - HEAD側のfrontmatter：`draft` / `editing` / `date` / `pinned`
   - `git show origin/main:<path>`でmain側の同じ欄と比べ、**このPRで公開状態が変わるのかどうか**を判定する
   - `date: coming-soon`は未公開の placeholder
4. `git log`でリネームが出たら、URLが変わる記事がないかを確認し、`public/_redirects`に301が入っているかまで見る
5. `grep -n "TODO" <変更した記事>`で、残っている図版・要確認のマーカーを実際に数える

## 説明文の構成

- **## 概要** — このブランチで何をしたかを2〜3文
- **## 公開される変更（マージすると本番に出る）** — 記事名と変更内容の表
- **## 未公開のままの記事** — `draft: true` / `editing: true`の記事の表。状態と内容を並べる
- **## その他** — タグ追加、プラグイン修正、シリーズの記事順変更など、記事本文以外
- **## マージ前に必要なこと** — チェックボックス。**実際に残っている`TODO`マーカーから作る**。前の説明文の項目をそのまま引き継がず、済んだものは消す

判定のルール。

- 公開される／されないの境目は、`draft`と`editing`で決まる。`project`と`event`には`draft`が無く、代わりに`editing: true`が本番で**本文だけ**を隠す（ページ自体は公開されている）ことに注意する
- すでに公開済みの記事に手を入れた場合も「公開される変更」に含める。読者から見える変更だから
- **URLが変わる記事があれば、表の外に警告として書く**。リダイレクトの有無も明記する
- 記事以外の変更（タグ、スクリプト、設定）は「その他」にまとめ、記事の表に混ぜない
- 各記事が新規なのか、書き直しなのか、他の記事からの切り出しなのかを1行で書く

## タイトル

- 中身とずれていたら（ブランチが伸びて別の作業が乗っているなど）、更新案を出す
- `feat:` / `fix:`の接頭辞と日本語というこのリポジトリの慣習に合わせる
- ブランチの主題を1つに絞れないときは、主要な変更を「と」「・」で並べる

## 反映

- 説明文はファイルへ書き出してから`gh pr edit <番号> --body-file <path>`で更新する（本文が長く、シェルのエスケープで壊れやすいため）
- タイトルは`gh pr edit <番号> --title "..."`
- 末尾の`🤖 Generated with [Claude Code](https://claude.com/claude-code)`は残す
